# dsh-tell-the-diff

DSH 右栏的**任务状态卡**：模型埋头执行时，让用户不用追问主对话也知道——这件事拆成了几步、现在第几步、卡在哪、下一步做什么。

α 版（0.1.0）只做确定性面板：读会话日志，不调用任何模型，不额外消耗 token。

## 它长什么样

右栏（`sidebar.right.pane.tab`）里的一张卡：

- **一行现状**：`正在修改文件 · src/app.js` / `空闲 · 上一步 12 秒前结束`
- **人话摘要**：模型通过 `tell_the_diff` 工具写的一句话，说明"现在到哪了"
- **拆成了几步**：待办/进行中/已完成/卡住，四种状态
- **需要你决定**：模型攒下的问题
- **最近做了什么**：工具动作 + 结果 + 用时
- **动过的文件**：读了什么、改了什么
- **页脚**：动作次数、出错次数、模型调用 0 次

## 怎么开

1. 启动 DSH，打开右侧栏（`Ctrl/Cmd + I` 或标题栏的右栏按钮）。
2. 在右栏起始页里选「任务状态卡」，或从 View 菜单打开。
3. 发一句话给模型，卡片自己亮起来。

## 数据从哪来

| 来源 | 提供什么 | 是否调模型 |
|---|---|---|
| `session/event` 事件流 | 工具调用、成功/失败、文件读写、轮次 | 否 |
| `tell_the_diff` 工具 | 模型自己写的一句话摘要、步骤、问题、风险 | 否（模型本来就那一轮在说话） |
| 一次 `GET /dsh-tell-the-diff/state?session=<id>` 轮询 | 把上面两样合成卡片 | 否 |

服务端只在内存里保留每个会话的一份派生状态（最多 40 个会话，空闲 30 分钟后回收）。它不是真相源：会话日志才是。

## `tell_the_diff` 工具

模型在任务开始、阶段切换、遇到阻塞、长任务每推进一段时调用一次。参数：

```json
{
  "plain": "在核对需求，还没动代码；等一下要先确认旧接口要不要保留。",
  "steps": [{ "title": "读现状", "status": "done" }, { "title": "改代码", "status": "doing" }],
  "questions": ["旧接口还要兼容吗？"],
  "risks": ["改动会影响两个下游脚本"]
}
```

工具描述里写死了两条纪律：**用非技术读者能懂的话**，**不要用比喻、黑话、文件名清单或代码术语**。

## 边界

- 只读、旁路：不改任务执行，不自动发消息，不自动审批，不抢主对话。
- 不复制文件树 / Git / 子代理视图（那是 `dsh-better-sidebar` 的事）。
- 不做跨会话方位（那是 `bearings` 的事）。
- 不录制全量 transcript：只留压缩后的活动、文件计数和最近 5 次检查点。

## α 的已知限制

- 轮询 1.5 秒一次；不做推送。
- 「还没解决的问题」区块里的中文标题目前是写死的（其余文案跟随浏览器语言）。
- 介入时机函数 `shouldSurface` 只到 `card`，`alert` 是 v0.3 的事；面板不主动弹窗。
- 没有异步摘要模型调用——这是 α2 的事，需要先证明确定性面板不够用。

## 开发

```sh
npm test          # node --test，26 个用例覆盖事件归约、人话映射、快照、介入判定、插件装配
```

插件源码在 `plugin/`，纯函数核心在 `plugin/core/monitor.js` 与 `plugin/core/store.js`。

## 安装

DSH 的插件管理里「添加插件 → 本地目录」，选中 `plugin/` 目录；或在会话里让 DSH 用 `plugin_manager` 的 `install_bundle` 安装这个绝对路径。

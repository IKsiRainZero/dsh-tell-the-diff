# dsh-tell-the-diff

> DSH 插件 · 会话路线图「这一路」 · α 阶段
> 不是对外呈现节目；是会话内的变化监视器。

## 一句话

模型埋头执行时，用户只看到快速滚动的工具调用和思考链，逐渐失去掌控感。**TellTheDiff 把「这一路怎么走过来的」从主对话里搬到输入框下面和右栏**：哪里落了地、哪里卡住换了路、此刻是什么状态。**默认不调用任何模型。**

## 现在能做什么（v0.3）

三个入口，一张卡。最省事的是**输入框正下方的一行**：`● 这一路 · 验证通过 · pnpm test … 打开`——会话有动静才出现，点「打开」进右栏看完整卡片。右栏标签条和起始页里也能到。

卡里有什么：

- **一行现状** —— 空闲时是 `空闲 · 上一步 12 秒前结束`；进行中是最近一个落点
- **人话摘要** —— 模型通过 `tell_the_diff` 工具写的一句话
- **落点** —— 这条路径真正改变了工作状态的地方：
  - `● 验证通过 · pnpm test`
  - `● 新建了文件 · a.md、b.md`
  - `● 改动了代码 · 3 个文件`
  - `⑂ 卡住了 · 「pnpm test」试了 2 次没通` / `⑂ 换过路 · …换了做法`
- **拆成了几步** —— 模型写过计划就用它的（标注「模型自己写的」），没写就按动作推断（标注「按动作推断」）
- **需要你决定 / 可能的风险 / 还没解决的问题**
- **角落一行** —— 文件数、动作数、出错数，以及文件名；只作同一视域内的旁证，不占版面

### 为什么是"落点"而不是"活动流水"

`read → grep → edit` 是准确的，但对读者没有意义：它说的是"跑了什么"，没说是"为了什么"。而"发生了什么"这一层已经被 DSH **轨迹**、**dsh-context**（文件活动 / 命令执行）占满了——再做一个更精细的版本只是换个排版。

真正没人的那格是**变化**本身：在那一刻，除了被选中的那条路，还有哪些路被关掉了。落点记录"工作状态确实改变"的瞬间；岔路记录"试过、没通、换了做法"。git 有前者没有后者，轨迹两者都没有。

### 计划从哪来

| 来源 | 什么时候 | 可信度 |
|---|---|---|
| **模型自己写的** | 模型调用了 `todo_write` 或 `tell_the_diff` | 它说的就是它想做的 |
| **按动作推断** | 模型没写计划时，由动作归并而来（摸清现状 → 动手改 → 跑验证） | 是"它实际做了什么"，不是"它打算做什么" |

两条都不需要模型额外付费：`todo_write` 是模型本来就会用的工具，推断则是纯函数。

## 怎么装

需要 DSH `0.2.2-rc.2` 或更新。

**方式一（界面）**：插件管理 → 添加插件 → 本地目录 → 选 `plugin/`。

**方式二（会话里）**：让 DSH 用 `plugin_manager` 的 `install_bundle` 安装 `plugin/` 的绝对路径。

装完需要**重启一次 DSH**（新 bundle 的 package 解析变化要求重启）。

## 怎么用

1. 打开右侧栏，在起始页点「任务状态」。
2. 给模型发一个任务。卡片自己亮起来，1.5 秒刷新一次。

模型在任务开始、阶段切换、遇到阻塞、长任务每推进一段时会调一次 `tell_the_diff`：

```json
{
  "plain": "在核对需求，还没动代码；等一下要先确认旧接口要不要保留。",
  "steps": [{ "title": "读现状", "status": "done" }, { "title": "改代码", "status": "doing" }],
  "questions": ["旧接口还要兼容吗？"]
}
```

工具描述里写死了两条纪律：**用非技术读者能懂的话**；**不要用比喻、黑话、文件名清单或代码术语**。

## 四个构件

| 构件 | 在哪 | 做什么 |
|---|---|---|
| 承载实体 `TaskMonitor` | `plugin/core/store.js` | 每会话一份派生状态；随会话存在，不跨会话；40 会话上限、空闲 30 分钟回收 |
| 监视工具 `tell_the_diff` | `plugin/index.js` | 模型写「为什么 / 还差什么」；查询路径不产生模型调用 |
| 呈现视图 | `plugin/client.js` | 右栏 tab；一张状态卡，不是聊天流 |
| 介入时机函数 | `plugin/core/monitor.js` 的 `shouldSurface()` | `silent` / `card`（长任务 ≥90s 或 120s 内 ≥2 次失败）；α 只到 card |

## 为什么它不会变成第二个 token 黑洞

- **默认零模型调用**：卡片内容是会话日志的改写，不新增请求。
- **工具描述有界**：参数模式固定几十个 token，不随会话增长。
- **不存全量 transcript**：每会话最多 20 条活动、10 条问题、5 次检查点、40 个文件。
- **一次轮询一个 GET**：1.5 秒一次，只回当前会话的派生视图。

## 与现有件的边界

| 现有件 | 它回答什么 | TellTheDiff 不做什么 |
|---|---|---|
| `dsh-better-sidebar` | 文件树、Git、任务、子代理、侧聊 | 不复制那些页；只做「这张任务现在到哪」 |
| `bearings` | 跨会话 / 跨线的方位 | 不做账本，只做会话内 |
| `dsh-context` | token 组成、上下文压力 | 不重复 token 仪表盘 |
| 主对话 | 任务执行与追问 | 不抢占、不自动发消息、不 steering |

## 不做

- 不做文件树 / Git / 子代理浏览器。
- 不做跨会话全景。
- 不自动 steering、不自动 approval、不自动发消息。
- 不做全量录制。
- 不做「另一个聊天侧栏」。

## 验证

```sh
npm test        # 28 个用例：事件归约、人话映射、快照、介入判定、store、Host 装配、Client 注册形状
```

成功判据（长期）：用户「现在做到哪 / 怎么样了」的追问次数下降；打开侧栏到理解状态的时间下降；token 开销小于节省的追问成本。不能测的如实写不能测。

## 已知限制

- 轮询 1.5 秒一次，不做推送。
- 「还没解决的问题」区块的标题写死中文；其余文案跟随浏览器语言，还没走 `ctx.locale`。
- `alert` 档与用户可调阈值未做；面板不主动弹窗。
- 没有异步摘要：那是有预算上限之后的事。
